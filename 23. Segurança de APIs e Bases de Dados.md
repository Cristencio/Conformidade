# 23. Segurança de APIs e Bases de Dados

## A. Autenticação e identidade da API
1. Exigir autenticação em endpoints privados.
2. Utilizar mecanismos adequados ao tipo de cliente.
3. Validar assinatura, emissor, audiência e validade de tokens.
4. Definir expiração curta para tokens de acesso quando adequado.
5. Permitir revogação de credenciais.
6. Rodar segredos e credenciais periodicamente.
7. Não colocar tokens em URLs.
8. Proteger credenciais de serviço.
9. Separar credenciais por ambiente.
10. Utilizar MFA para operações administrativas.
11. Não aceitar algoritmos de token inseguros ou inesperados.
12. Rejeitar tokens malformados.
13. Evitar mensagens que revelem existência de contas.
14. Registar autenticações relevantes.
15. Aplicar rate limiting em autenticação.

## B. Autorização e controlo de acesso
16. Verificar autorização em cada endpoint.
17. Verificar acesso ao objecto específico, não apenas ao tipo de função.
18. Prevenir BOLA/IDOR.
19. Aplicar menor privilégio.
20. Separar funções administrativas e de utilizador.
21. Não confiar em IDs ou papéis enviados pelo cliente.
22. Impedir acesso transversal entre organizações/tenants.
23. Validar propriedade dos recursos.
24. Controlar operações de leitura, criação, alteração e eliminação separadamente.
25. Registar alterações de permissões.
26. Rever permissões periodicamente.
27. Impedir escalada horizontal e vertical.
28. Proteger endpoints internos.
29. Definir autorização para tarefas assíncronas.
30. Testar cenários negativos de autorização.

## C. Validação e tratamento de entradas

## Critério geral
Nenhuma API ou base de dados deve ser considerada segura apenas por possuir autenticação. É necessário demonstrar autorização por recurso, validação, integridade, protecção de dados, auditoria e recuperação.
