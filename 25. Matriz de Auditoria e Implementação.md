# 25. Matriz de Auditoria e Implementação

## Campos
| Campo | Finalidade |
|---|---|
| ID | Identificador único do requisito |
| Documento | Área a que pertence |
| Requisito | Regra a verificar |
| Aplicabilidade | Obrigatório, condicional ou não aplicável |
| Natureza | Legal, normativa, contratual ou boa prática |
| Prioridade | Crítica, alta, média ou baixa |
| Estado | Não iniciado, em curso, conforme, não conforme ou bloqueado |
| Evidência | Teste, código, política, registo ou documento |
| Responsável | Pessoa ou equipa |
| Prazo | Data de conclusão |
| Observações | Risco, dependência ou justificação |

## Regras de auditoria
1. Não marcar um requisito como conforme sem evidência.
2. Justificar requisitos não aplicáveis.
3. Distinguir obrigação legal de boa prática técnica.
4. Priorizar riscos de segurança, privacidade, pagamentos e integridade.
5. Registar a versão do sistema auditado.
6. Repetir testes após correcções.
7. Manter histórico de resultados.
8. Definir responsável e prazo para cada não conformidade.
9. Rever a matriz quando o produto, arquitectura ou legislação mudar.
10. Não considerar a checklist substituto de testes técnicos ou parecer jurídico.
